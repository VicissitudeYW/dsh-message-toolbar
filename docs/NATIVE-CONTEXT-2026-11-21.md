# 1.11.0 原生上下文分支与验证

本轮基线：`996bc37` / 1.10.0。目标是让回答切换、编辑与删除决定后续模型实际读取的历史，同时只修改插件。设计见 [spec](superpowers/specs/2026-11-21-native-context-branches-design.md)，步骤见 [计划](superpowers/plans/2026-11-21-native-context-branches.md)。

## 解决方式

一个逻辑会话可以包含多个真实 DSH session。插件用公开 `agents.create({ seed })` 保存独立历史，通过回答选择器和原生会话导航切换活动路径。

例如，问题 Q 有回答 A、B：重答 B 时，新请求只包含 Q 之前的上下文和 Q，不包含 A；在 B 下追问 C，使用的是 Q/B/C。切回 A 时恢复 A 自己的后续，不能把 B 的后续混过来。编辑和删除也生成独立历史，原记录留在版本树恢复。

| 操作 | 模型上下文及保留内容 |
| --- | --- |
| 重答 / 换模型 | 问题之前的完整前缀 + 一次问题；没有旧回答及其后续。保留原生工具、思考与 streaming。 |
| 选择回答 | 将真实 composer 切到所选分支；后续追问读取该分支的历史。 |
| 保存问题 | 新分支包含改后的问题和现有回答，不调用模型；截断后续。发送则直接创建重答分支，不先写旧显示状态。 |
| 编辑回答 | 新分支替换最终助手正文，保留配对工具记录，清除旧 provider replayState；回答身份不变，选择器不增项。 |
| 删除回答 | 新分支移除该轮全部助手/工具记录及后续；有其他回答则切到幸存回答，无其他回答则仅留问题。 |
| 删除问题 | 新分支只保留该问题之前的历史；问题、回答及后续仍可从旧版本恢复。 |
| 旧数据同步 | 将旧 runs/replays、文本备选、问题覆盖和隐藏状态物化成原生日志；不能安全理解的压缩或跨回答事件引用会报错。 |

新 marker 保存完整身份快照、来源、操作和删除关系，不作为提示词正文发送。持久化成功后才回应，缺少存储 listener、flush 返回 false 或写入失败不会被当成成功。旧显示写入 API 明确拒绝陈旧客户端。

## 导航与数据保护

- 目标输入框挂载后才执行带 token 的 focus；生成或准备导航不会归档当前来源。
- 同族导航准备与归档串行，过期 token 被拒绝。刷新可从持久导航状态继续收尾；损坏的导航记录报错并保留原文件。
- 只合并有本插件 marker 的版本；原生独立 fork/subagent 不会因为共享 parentSession 而被自动归档。
- 新分支使用源事件的独立副本；未修改原 session、个人状态、已安装插件或 DSH 安装文件。
- 文件副作用单独处理：上下文分支不会自动撤销磁盘改动，沿用明确确认后的安全回退。

## 验证方法

`npm test` 执行构建、既有 host/client 检查与 node:test 回归。覆盖独立 seed、稳定问题/回答身份、旧数据迁移、真实会话导航、错误/并发、翻译、附件、状态锁和文件回退。

可选的 `test/native-context.integration.mjs` 使用本机 DSH `0.2.2-rc.5` 的真实 `Session`、agent loop、消息投影和 JSONL 持久化。所有数据放进临时 home，模型替换为脚本 adapter，工具是只读固定结果；不调用云模型。它通过真实插件路由创建会话，直接检查 `GenerateOptions.messages`，再 dispose/resume 验证冷重载。

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
$scriptUri = ([System.Uri](Resolve-Path 'test/native-context.integration.mjs').Path).AbsoluteUri
$env:NATIVE_ASAR = '<DSH 安装目录>\resources\app.asar'
$entry = "process.argv=[process.execPath,'test/native-context.integration.mjs',process.env.NATIVE_ASAR]; await import('$scriptUri')"
& '<DSH 安装目录>\DeepSeek Harness.exe' -e $entry
```

真实引擎已通过重答隔离、两个分支各自追问、保存问题不生成、编辑回答、问题/回答删除、工具配对、旧状态迁移、临时模型恢复与冷重载检查。

## 实现选择及代价

1. 产品只依赖公开 DSH 服务，不导入私有模块或打包宿主 session 实现；历史无法安全理解时拒绝操作。代价是某些旧压缩记录需要用户回到压缩前版本。
2. 完整复制历史作为 inherited seed，seed 边界由原生 Session 构造器生成；问题保留但回答删除时，在 child setup 中闭合该轮。已用真实持久化及冷重载验证，兼容结论仍限于实测版本。
3. 停用旧显示修改写入接口，保留读取、翻译与迁移。代价是未刷新/未更新的客户端必须更新并重启，不能继续调用旧接口。

## 边界

实际验证版本为 DSH `0.2.2-rc.5`；最低依赖提高到该版本。纯插件使用公开能力减少对宿主实现的依赖，未来公开 API 若变化仍需兼容验证，不能承诺任何上游更新都不会影响插件。

分支增加存储，不物理擦除原日志；切换保存的是会话历史而非工作目录快照。旧版显示修改在同步之前仍然使用原始日志，输入框会提示同步。压缩/替换后的历史可能需要回到压缩前版本才能操作。保存问题保留旧回答，这份回答不会自动针对新问题重新计算；需要新回答时应点击发送。

本轮没有完整 DSH GUI、真实 provider 或云模型验收，没有 npm 发布、已安装副本同步或应用重启。并排比较、批量操作、朗读等仍未加入，属于后续产品范围。
