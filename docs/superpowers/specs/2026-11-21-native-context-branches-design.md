# 纯插件会话上下文分支设计

用户已选择只改插件，沿用此前自主实施、验证和推送授权。本设计将回答选择与真实模型历史绑定，不修改 DSH 安装文件或私有运行时。

## 方案与依据

- 修改 DSH 核心的活动历史：用户明确排除。
- 继续隐藏消息或过滤某个 provider 请求：无法持久、完整地保持工具调用和冷重载一致，排除。
- **采用真实 DSH 会话作为分支**，插件提供一个逻辑会话的入口、回答选择与版本树。通过公开 `agents.create({seed})` 创建派生历史，保留原会话只读。分支间导航使用 `uiWorkspace.openSession`，目标挂载后再归档旧入口。

已用本机 0.2.2-rc.5 运行时及临时 JSONL 存储验证：prefix seed 重答、修改副本内的消息内容、冷重载及后续请求均可工作。官方 tag 为 `9c2670d3bce5275e0d1610272958121af87787bb`；当前上游 HEAD 为 `2e39e70496aa02986ca6a820c5d497e816b69d7e`。Context7 本轮网络 fetch failed；公开源代码、官方远端引用与实际运行时交叉验证代替不可用的在线文档检索。

## 行为契约

1. 重答/换模型：从问题之前的精确事件前缀创建分支，只提交一次该问题。旧回答与其后续追问不进入新请求。原生 agent、工具、思考、streaming 保留。一次模型选择结束后恢复此前会话模型。
2. 回答选择器：位于删除按钮右侧，只有多个有效回答时出现；选择会导航到该回答真实分支，后续追问使用该分支上下文。该分支已存在的后续追问随分支恢复，不能混入另一分支的后续。
3. 编辑问题：保存生成包含新问题和现有回答的派生历史，不调用模型；发送原子生成新问题的重答分支，不能先在旧会话保存一份显示覆盖后仍向旧会话发送。两种操作均截断不再可信的后续；原分支保留。
4. 编辑回答：生成包含改写回答的派生历史；保留该回答的身份，选择器不增加一项。保留该轮已有配对的工具调用/结果，修改最终助手文本，原始记录不动。截断该轮后的后续。
5. 删除回答：从该轮问题之前至已进入的问题生成只含问题的闭合历史，去除该轮全部助手/工具结果及后续。若有其他回答，切换到邻近回答并将所删除选择标为不可选；若无其他回答，保留问题。以后重答只计一个有效回答。
6. 删除问题：生成该问题之前的闭合前缀，从新上下文去除整个问题、回答及后续，原分支留在版本树中恢复。界面文案明确后续留在旧分支。
7. 元数据：新 marker 保存源分支、目标轮、逻辑问题身份、回答身份及编辑/删除关系；使用可忽略记录，不注入模型正文。不同问题不能仅凭相同 turn 数合并。只对插件拥有的版本执行自动归档，不归档 DSH 原生独立 fork/subagent。
8. 旧数据：保留旧插件状态。对旧 runs/replays/显示覆盖在首次需要上下文操作时建立规范分支，选中的旧回答必须变为真实历史，不能继续追加旧式重答。旧 raw API 若无法保证语义，应明确拒绝或走迁移，不能静默退回显示模式。
9. 持久化：每个分支在回应成功前 flush；失败时保持源可用。导航失败不归档源；目标挂载后归档，刷新可恢复待完成焦点；不吞掉激活错误。
10. 不自动撤销文件副作用；沿用已验证且需用户明确点击的文件回退。无需修改 DSH，亦不安装新 DSH 构建、不调用真实付费模型、不更改个人会话。

## 实现选择

使用 seed 的独立副本，仅在新分支内编辑内容；不修改源事件、不注册自定义 model projection、不伪造未闭合 turn。answer-delete 采用问题前缀及结构闭合，删除工具配对整个单元。版本头保存 lineage，持久插件状态记录选择去重/删除及 continuation；活跃分支是原生 composer 的真实 session ID。

## 验收

- 插件实际 HTTP 路由在真实 DSH native loop 上运行，抓取 `GenerateOptions.messages`，证明重答无旧回答、选择旧/新回答后追问不同、编辑与删除真实生效。
- flush/dispose/resume 重复上述上下文检查；包含有工具调用的回答，验证配对与冷日志读取。
- 问题保存不发请求，发送只发一次；编辑回答不增加选择；删除最后回答后重答无幽灵选项。
- 界面导航失败/延迟/快速连续切换、仅一个侧边栏入口、无关原生 fork 不被归档。
- 保留现有翻译取消/附件/文件回退/持久锁回归；完整测试、构建、打包和独立最终审查后推送 GitHub。
