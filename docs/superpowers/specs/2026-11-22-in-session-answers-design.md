# 同一会话内重答与切换

工具栏操作继续使用原来的 DSH 会话 ID。重答和换模型需要将同一问题的新答案加入消息下方的选择器。切换回答恢复该回答的后续。下一次模型请求包含可见路径上的问答与工具记录。会话列表、归档和置顶通过 DSH 自己的入口管理。

DSH 0.2.2-rc.5 的 agent 请求不可变，`agent/request` 只能修改调用配置，原生会话分支会多出会话 ID。历史替换事件会永久改变原生模型历史。采用 DSH 公开的 `llm/stream` 生成扩展点。对于有工具栏修改的会话，由插件提交一份保留模型、工具和取消信号的选中路径请求，原生 agent 接收流并照常运行工具。未修改的会话与普通翻译等辅助请求沿用 DSH 原请求。DSH 的原生记录依然保留实际发生的各轮，工具栏状态记录哪一条路径当前可见。DSH 自带的原始日志与模型回放仍基于其原生记录。

工具栏状态和实际消息 ID 一起保存。换模型只作用于本次重答。编辑保存与删除单条消息保留当前路径上的其他轮次。一个问题有多条回答时，删除当前回答优先选中前一条，并恢复它已有的后续消息。旧版 runs、replays、prompts、answers 和 hidden 在同会话内解释，沿用上次选择。上一版创建的真实会话可以在旧版本列表里显式访问。

仅在压缩摘要确实覆盖当前选中的连续原始消息且原文未改动时复用摘要。如果旧摘要与所选回答不匹配，从原始事件恢复相关历史。DSH 压缩请求涉及未选中版本时终止该次摘要，避免把已排除的回答写回上下文。超长历史仍受模型的上下文容量约束。

验收使用已安装 DSH 引擎与隔离存储，断言前后 DSH 会话 ID 与工作区成员、归档、置顶一致。记录实际请求验证旧答案隔离、答案各自的续问、工具配对、指定模型及恢复、编辑删除、旧状态和重新打开。客户端保留原生渲染及大纲，按同一套历史选择显示消息。
