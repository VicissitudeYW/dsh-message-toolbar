# 模型切换恢复与跨进程状态设计

## 意图

在插件自身可控的范围内继续提升可靠性：单次“切模型重答”完成后恢复该会话此前的模型选择；多个 DSH 进程同时运行时，插件状态读写不再因各自缓存互相覆盖。目标用户是同一 Windows 用户下并行运行 DSH 桌面/开发实例的插件使用者。

## 目标与边界

- 重答期间用用户指定的模型；排队消息已被认领后，即使工具解析、prompt 组装等步骤在 `user/message` 落盘前失败，仍在对应重放轮结束后恢复重答前有效的模型与显式 reasoning effort。
- 只在当前有效选择仍是本次临时选择时恢复，保留后续由用户或其他功能作出的模型选择。
- 按跨进程互斥顺序读取最新状态、应用本地 mutation 的 before/after 差异、原子写回，避免不同进程的陈旧整文件快照互相覆盖。
- 仍兼容 schema 1，不增加生产依赖，不读写真实会话作测试。
- 同会话重放的历史上下文隔离继续受 DSH 持久化会话模型约束，本次不以插件显示层变通实现。
- 不提供针对恶意本地进程、网络文件系统或任意外部编辑 `state.json` 的安全保证。

## 当前行为与根因

- `queueAnswerInPlace()` 通过 `agent.model.select()` 选择重答模型。DSH 在匹配请求头之后将该选择折叠为 `lastUsed`，因此选择会延续到后续请求。插件目前没有按此次重放完成来恢复前一选择。
- `createDurableState()` 在每个 Node 进程内缓存完整 JSON，并在延迟 flush 时原子替换状态文件。原子替换避免半文件，却不协调两个进程：后写进程可能用旧缓存覆盖先写进程的不同字段。

## 方案与取舍

### 模型恢复

1. 在 `agent/turn-stopping` 中同步恢复：正常完成路径及时，但错误/取消路径不保证经过该钩子，且该钩子仍可因新 steering 继续当前轮。
2. 等 `agent.whenIdle()` 后恢复：可覆盖终止结果，但若重放期间已有新输入排队，会让新输入也先使用临时模型。
3. 监听会话事件中本次排队用户消息所对应的 `turn/end`，在同步事件分发结束后恢复：精确到本次重放且覆盖完成、失败和取消。恢复前比较当前模型，避免覆盖较新的选择。**采用方案 3。**

### 状态写入

1. 仅做陈旧版本检测并报错：可防丢失，但并行进程会经常要求手工重试，不能满足共享状态需求。
2. 不带修改前基线的整快照深度合并：无法区分未修改字段和主动删除，容易保留已删除值或丢失并发追加。
3. 用同一跨进程锁串行化“从磁盘读取最新状态、应用本进程待提交 mutation 的差异、原子写回”，并在外部版本变化时刷新进程缓存：保留现有 schema，解决不同会话、不同字段和集合追加冲突。**采用方案 3。**

## 实施决策

- 以重放消息 ID 与当前会话的 `turn/start` / `user/message` 事件关联真实重答轮，避免假设期间没有其他来源排队新消息。
- 重答轮结束事件处理函数只安排一个微任务；微任务在同步 `session/event` 分发返回后执行 DSH 的公开模型选择 API。
- 恢复使用重答前完整有效选择；若找不到此前模型、选择 API 不可用或当前路由/effort 已变化，则不伪造恢复。
- `agent/inbox/claimed` 的消息 ID 和目标 turn 提供早期失败关联；记录的 `user/message` ID 仍作为补充确认。恢复读取或模型选择若抛错，会记录错误并清理监听器，不使异步异常逸出宿主；同步排队失败仍保留原始错误。
- 状态锁先写入完整 PID/token 元数据，再通过同目录独占 hard link 原子发布；有界等待，只有确认所有者进程已退出才回收。清理操作由带唯一 owner 标记的目录互斥，只有成功移除旧标记的进程才能移除该空目录，避免竞争者删掉新清理者的保护目录。
- 元数据缺失、损坏或未知的锁，以及所有者尚未明确的清理目录，默认保留并超时报错。强杀发生在清理标记已移除、目录尚未移除之间，可能需要停用相关 DSH 进程后人工检查；安全性优先于猜测锁已失效。本地文件系统必须支持同目录 hard link 与原子 rename。
- 每次 mutation 在独立 draft 上执行，仅记录实际改变的字段；轮号数组按值、备选按回答 ID、附件按类型与 attachmentId 合并增删。删除空容器只减去本地基线中的记录，保留并发新增项；同一标量冲突以最后提交的修改为准。未知结构数组退回深度相等的增删合并，不提供通用列表重排语义。
- 读取前捕获文件版本，避免读完旧内容后误记新版本而长期缓存旧值。写入仍用唯一临时文件、fsync 与 rename。
- 通用 delta 合并后只修复仍存在的回答分组：结合问题 root、持久 replay 身份及隐藏标记重建可见成员，修正 active/model 元数据；显式删除的完整分组不会仅因 replay 身份重新创建。
- 保留本地 mutation 的即时读后写语义及现有短延迟 flush；用隔离子进程测试竞争，不操作用户的 `~/.dsh`。
- 不清理翻译/回答数据；不升级 schema；不改变当前模型默认规则，只为显式传入另一模型的重答增加临时选择恢复。

## 验收

- 成功、错误或取消结束的重答轮，包括在 `user/message` 记录前失败的已认领重放，会在同步事件分发后恢复原选择；恢复 API 抛错不会崩溃宿主；被替换为新模型的后续选择保持不变；非目标会话或轮次不触发恢复。
- 两个独立 Node 进程并发写入不同会话、同一隐藏集合中的不同轮号、首次给同一轮增加不同备选后，磁盘状态包含全部修改；已加载旧缓存的进程也能读取外部提交。
- 对同一记录改不同字段，或删除本地最后一条记录时，其他进程新增的字段与记录仍保留；读取时发生文件替换也能在下次读取刷新。
- 并发删除最后成员与追加新回答时，尚未隐藏的原回答仍留在环中；刷新热缓存也维持此分组约束，但故意整体删除的分组不会复活。
- 活锁与活清理者不被误删；可识别的死进程锁及清理标记可以回收；未知所有者保守超时，原文件保持有效且 mutation 可重试。
- 既有状态持久化、host/client 回归、构建、打包清单检查通过。
- 不把隔离测试描述成真实 DSH GUI 或模型调用验收。
