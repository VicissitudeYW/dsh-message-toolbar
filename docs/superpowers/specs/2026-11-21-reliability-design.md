# 消息工具栏可靠性重构 spec

## 依据与决策

本轮由用户授权自主调研、编写 spec、实施、验证并推送 GitHub。需求依据为开发会话的 138 条直接用户消息（2026-10-21 至 2026-11-21，北京时间）。原始会话、个人工作区、模型凭据及运行状态不进入仓库。冲突需求以最后一次明确说明为准。

基线：提交 `8cf98f7`、插件 1.8.8、本机 DSH `0.2.2-rc.5`。现有 host/client 测试通过，但缺乏持久化、文件回退、并发刷新等边界覆盖。

方案比较：整套重写会丢失一个月积累的宿主兼容逻辑；只继续追加条件分支难以验证。采用渐进式重构：保留 Cordis 插件入口和现有原生 UI 接入，将危险或可独立验证的边界移到小模块，用行为回归测试约束。保持无生产依赖，不引入新的前端框架。

## 必须保留的交互

| 能力 | 最终要求及历史定位 |
| --- | --- |
| 重新生成与切模型 | 使用真实 agent、工具、原生流式过程；留在同一会话；重新生成也保留备选（seq 22225）。不自动创建可见分支。 |
| 删除 | 用户消息删除整轮，回答删除该回答及附属行，不能归档当前会话。删除备选后不能切回它；只剩一个时无切换器（seq 20156、22330）。 |
| 失败 | 停止、503、额度耗尽、空回答时仍有重新生成、模型、删除；不出现无内容的编辑或翻译（seq 29425）。 |
| 用户编辑 | 保存只修改显示与后续重放输入；发送另行触发原生 agent。会话标题保持不变（seq 19893、15495）。 |
| 回答编辑与复制 | 在原位编辑 markdown，保存覆盖且保留渲染，不增加备选；复制当前所见文字（seq 7673）。 |
| 附件 | 支持选择、拖放、剪贴板图片；上传使用 DSH 接口；编辑后和重启后均显示，重新生成不丢失、不重复。 |
| 翻译 | 点击后选语言；段落原译对照，流式进度；代码、公式、已有目标语言保持；不设置人为最大 token；修改或切换回答不得显示旧译文。 |
| 大纲与外观 | 隐藏消息、重放提问和备选切换同步影响大纲；不能阻止后续新消息更新。匹配原生明暗色、菜单、图标及引用高亮。 |
| 文件回退 | 回答改过文件时先确认；文件内容不再匹配时拒绝覆盖；新增、删除、空文件、首行及换行符都需测试。 |

## 可靠性约束

1. 请求字段在产生状态或 agent 副作用前统一校验，拒绝非法轮号、附件、模型及危险对象键。
2. 原有 schema 1 状态兼容；无效 JSON 不得被悄悄覆盖，失败 mutation 不得泄漏部分状态。成功的交互变更必须具备明确落盘机制。
3. 同一会话重放需串行或拒绝重叠，不能让两个请求预测同一轮；不得静默丢弃 `group` 等协议字段。
4. GET 旧快照不得覆盖更新的 mutation；GET 正在进行时发生 invalidate，必须补抓 mutation 后的新快照；loading 必须最终结束。
5. 流中断或 malformed frame 必须报错，不把不完整内容标记为成功；释放 reader 锁。
6. 生成包必须与源文件一致；测试不依赖手工运行 build。发布包含全部运行模块，测试不改用户真实状态。

## DSH 兼容与边界

官方资料通过 Context7 与官方源码交叉核对；本机版本以 `dsh --version` 实测为准。对照官方 tag `dsh-v0.2.2-rc.5`（`9c2670d`），而非假设 master 与本机一致。现代 Session 有 model-visible surface，append-only 日志与模型上下文不是同一概念；重放的上下文隔离只能通过已验证的公开契约实现，不能写坏日志或臆造 API。旧版缺少能力时需明确兼容策略，不能偷偷退回无工具的纯文本生成。

## 验收与交付

- 每个修复有先失败后通过的回归证据；全量 `npm test`、构建一致性、语法与打包检查通过。
- 用脱敏夹具模拟真实 DSH 事件和真实文件系统；如不能完成 GUI 或真实模型调用，交付中明确说明，不能把模拟测试写成实机验证。
- 独立代码审查，处理可复现的严重/重要发现；文档记录实际修复与剩余限制。
- 使用工作分支保留原 main，完成后 fast-forward 合并并推送用户明确指定的 GitHub 仓库，不强制推送、不发布 npm、不重启用户正在使用的 DSH。
