# 版本模型展示修复设计

## 目标

当工具栏使用备选模型创建重答版本时，回答卡片、版本树和回答选择菜单应继续显示该回答实际使用的模型，即使生成结束后插件已把会话 composer 恢复到重答前的默认模型。

## 根因

每个版本 marker 的 `effect.model` 记录了该次显式换模型操作。`sessionParsedData()` 同时从完整事件日志推导会话当前模型；重答完成后的恢复事件会让这个值回到默认模型。`tree()` 先写入 `effect.model`，随后又展开 `parsed.model`，后者覆盖了 marker 模型。回答正文对应的 `answerModel` 已经优先使用实际 assistant source，因此主要错误落在 `versions[].model` 及依赖它的展示路径。

## 约束与行为

- 只修改插件，不修改 DSH 本体、已安装副本或用户会话。
- 显式版本模型优先：`effect.model` 存在时，版本 `model` 必须等于它。
- 没有显式模型的普通编辑、删除、恢复版本继续使用解析出的会话模型。
- 实际模型请求和恢复逻辑保持不变；本次只修复 host 投影的元数据。
- 回归测试必须通过真实 host harness 的 `GET /message-toolbar` 边界验证，不能只断言私有函数或源代码文本。

## 验收

1. 在备选模型重答后模拟 `turn/end`，确认 composer 恢复默认模型。
2. 读取版本树，确认该版本仍标记备选模型，回答选择项也使用实际回答模型。
3. 普通无模型版本仍显示默认模型。
4. 通过完整测试、构建、差异检查和打包预览。
